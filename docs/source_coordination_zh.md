# 来源协调

## 职责

来源会话由 `SourceScanBinding` 统一拥有读取拓扑、尾部策略、扫描适配器和
`initial_cursor_factory` resolver；`IngestionSourceAdapter` 只实现
`scan_next(cursor, budget)` 和纯位置运算 `advance_cursor(cursor, records)`，不再解析会话
初始位置。binding resolver 在空的持续来源尚无 scan view 时可以返回 `None`，控制器随后
重试同一个 binding；planner 会锁定该 resolver，之后不会回查 adapter 或重新读取最新
快照来替代初始位置。来源扫描返回有序结果和不透明位置。来源适配器负责数据身份、固定版本、文件位置及位置编码；Fluxway 不解析
Iceberg 快照，也不要求写入方提供专用元数据。
生产与消费互相不可见；Fluxway 不要求生产者通知、共享断点、日志或水位。来源进度由
Controller 所有的显式扫描和确认事件推进，source-progress supervisor 不使用定时轮询。

范围读取与来源扫描是独立能力。能读取某种格式的指定行，不代表该来源已经提供
有界扫描和可恢复位置；接入规划组件必须实现扫描契约。每个适配器必须单独实现并验证
该契约；通用接口本身不代表所有存储格式都已接入。

`unit_cursors` 与有序区间一一对应，提供来源拥有的区间起点。适配器的
`advance_cursor(cursor, records)` 只做位置运算，不访问存储；结果的 `cursor_at`
选择已消费前缀对应的起点。这些定位信息留在控制面，不进入工作进程布局。

`LayoutUnitDescriptor.slice` 是编译器、窗口规划和内存来源共用的区间切分方法，
保持物理坐标和原始编码。`SourceScanStatus.from_scan` 根据记录数、范围是否扫完
及来源是否有限统一推导状态；适配器提供事实，不再各自实现状态分支。

`IngestionLayoutPlanningComponent` 负责拼接扫描结果、保留未满批尾部、编译和发布窗口。
编译器先固定逻辑训练步的数据，再分配给当前读取进程。读取进程只读分配的区间，
不能在恢复时改读最新表状态。

`LogicalWorkLedger` 管租约、读取完成确认和逻辑进度。读取完成不代表下游已经消费，
也不代表模型已经保存；共同检查点成功发布才推进持久化边界。

来源账本不再从训练图推导“共同下游消费前缀”，也不要求来源之后是一条线性路径。
来源的候选切点由来源工作确认按逻辑步连续推进；来源领取只受来源自己的在途窗口限制。
训练图中的扇出、汇合和条件边由依赖边流量控制与整图排空处理，不能反向改变来源身份
或伪造来源书签。

现有传输额度图只覆盖远程依赖，不能代替来源账本的租约和候选切点；按到达次数触发的
局部完成次数也不能直接写入持久来源位置。复杂图仍需通过整图排空和共同检查点验证，
不能把通用扫描接口视为任意图的恢复保证。

## 预算与窗口

`SourceControlConfig` 拒绝未知字段，支持以下配置：

| 字段 | 含义 |
| --- | --- |
| `planning_window_steps` | 一次期望准备的完整训练步数 |
| `max_in_flight_steps` | 相对来源候选切点的预取上限 |
| `max_planning_records` | 记录数预算 |
| `max_planning_units` | 读取区间数预算 |
| `max_planning_descriptor_bytes` | 所有读取进程的实际编码任务描述总预算 |

各类限制独立；原生元数据读取限制由来源负责，Fluxway 限制扫描行数和区间数，并测量实际编译的任务描述。一个完整训练步
必须能放入预算。尾部跨扫描结果、跨快照保持顺序，非终态不能丢弃或补齐；有限来源结束时
才按声明的尾部策略处理一次。

授信上限为当前窗口末尾与 `candidate_cut + max_in_flight_steps` 的较小值。读取进程到达
已发布窗口末尾时，使用条件等待下一个连续 activation；不会轮询、隐式重试，也不会因
窗口边界产生 `KeyError`。规划由显式进度事件触发，并根据已有的窗口和在途限制推导有界
提前量。窗口结束不强制模型保存。
`candidate_cut` 表示来源工作已经连续确认到的位置，只用于限制来源自己的在途范围；它
不是整图已经保存的切点。整图持久书签仍只能由共同检查点提交。
窗口结束不强制模型保存。扫描结果的可读、继续扫描、等待、结束状态不等于保存状态；空轮询
不是来源结束。

## 发布与生命周期

Controller 的 source window 进度由一个 `SourceProgressSupervisor` generation 监管。该
supervisor 唯一持有事件唤醒、规划执行、失败观察和 stop/join；Controller 状态转换不再维护
第二个轮询 task 或定时器，checkpoint resume 也不会重复 source startup。窗口规划在
Controller FSM 锁外执行，Controller 边界只传递有界唤醒和类型化失败事件。activation
发布后会唤醒等待新 step 的所有 worker admission。

阻塞元数据读取使用既有输入输出执行设施，编译使用既有进程池。调用者取消等待不
撤销组件已经接受的操作；关闭时拒绝新工作，等待既有工作结束并释放资源，异常可见。

发布先验证预算和区间覆盖，再一起安装窗口、来源位置、尾部和账本记录。激活只分发
任务描述，不生成另一份规划身份。物理绑定与放置改变不能改变逻辑批次内容。

窗口是预取边界，不是丢弃边界。planner 保留但尚未消费的区间继续留在唯一 pending 状态，
在下一个连续 activation 中复用原 source work identity。终态 activation 发布结束位置；
超出结束位置的请求返回类型化 `SOURCE_EXHAUSTED`，随后由整图排空和正常检查点切点收尾。

有规划接口不等于应用已经接通完整的事件驱动补充窗口和停止流程。只有历史条目而没有新
记录的目录数据块，需要联合验证有界推进和唤醒，不能在一次调用里无限扫描。

## 保存与恢复

复用控制面、驱动进程和工作进程的组件注册表。规划组件负责与共同保存点对齐的来源
状态，来源控制组件负责逻辑进度，工作进程组件保存模型和优化器。驱动进程组件只保存
自身状态；当前来源激活组件保存为空，恢复后重建任务分发。

来源保存消费书签，恢复后按当前窗口长度和读取进程数重新规划、预取，
保持全局批次大小和有序记录不变。纯预取内容、待拼接尾部和旧窗口摘要不作为来源
持久状态；影响未来结果的算子状态仍须共同保存。物理进程、租约和迭代器重新创建。
重放所需的来源历史必须仍然存在，缺失时失败，不重新从表头开始。

规划组件保存与共同检查点对齐的消费书签和来源约束；来源账本保存逻辑工作进度。
恢复时按已提交书签重新规划窗口，并由当前读取拓扑重新建立租约和任务分配。窗口、尾部、
租约和预取缓存属于运行期状态，不属于来源的持久检查点状态。模型和优化器等影响未来结果
的状态必须参加同一检查点。

扫描定位信息按已提交的持久切点回收。单次扫描和单个窗口的上限不限制两次保存之间的
累计驻留量；应用应根据检查点频率配置来源历史保留策略。
